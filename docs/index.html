Lab 2 · who may call what

Roles live in the token, and the token is signed

Cognito puts the user's groups in the access token. API Gateway's JWT authorizer checks the signature, issuer, client and expiry before any Lambda runs, so a forged token costs nothing. Roles are assigned server-side by the post-confirmation trigger: you can sign up as a buyer or a provider, never as an admin.

Lab 4 · exactly once

Stripe will repeat itself. Licences must not.

Webhooks arrive at least once: sometimes twice, sometimes late, sometimes after your endpoint failed and Stripe retried. The handler verifies the signature, then applies the effect and records the event id in one DynamoDB transaction guarded by the order's state. A duplicate fails the guard and changes nothing. Turn up the chaos, run a batch of checkouts and audit the result.

Each row is one buyer. The square is the moment the card is confirmed in the browser; every dot after it is Stripe knocking on the webhook. A red dot is an attempt our endpoint "missed", which Stripe retries 5 seconds later. An amber dot is a second copy of an event that was already applied: the transaction's condition on the event id fails, the handler answers 200, and nothing changes. Only one green dot per row can ever exist.

Mixed card runs include a decline followed by a retry (grey, then green) and a 3-D Secure challenge approved after a pause.

Lab 5 · what buyers say

Sentiment you can read token by token

Each review is scored once, when it is written, by a rule-based lexicon model built for software reviews: word valences, negation, boosters, "but" clauses, capitals and exclamation marks. It runs in under a millisecond, explains every point of its score, and gives the same answer every time, so product aggregates can be kept as exact integer counters and audited.

Lab 6 · you may also like

Two signals, added together

Content similarity (shared tags, same category) works from day one. Co-purchase similarity, the cosine of two products' buyer sets, is kept as atomic counters written during fulfilment. The shipped score is content + ½ × co-purchase. Build a library and watch each recommendation split into the two parts.

Under the bonnet

How it is built

One core package holds the domain logic and the HTTP routes. Thin adapters run it on AWS Lambda; the local runtime runs it in Node and in this page. The SAM template is generated from the route table, so the deployed API cannot drift from the code.

SoftHub-Lab/
├─ packages/core/src/      domain + API (runs on Lambda, in Node, in the browser)
│  ├─ api/                 routes: catalogue, shop, provider, admin, webhook
│  ├─ store.js             table port + DynamoDB emulator (conditions, GSIs, streams, capacity)
│  ├─ keys.js              single-table key design + access patterns
│  ├─ auth.js              roles, JWT checks, local user pool
│  ├─ payments.js          webhook signatures, fees, test cards
│  ├─ license.js           HMAC licence keys with a typo-proof checksum
│  ├─ sentiment.js         lexicon sentiment + aspects + summaries
│  ├─ recommend.js         content + co-purchase recommendations
│  ├─ runtime.js           the whole cloud in one process
│  └─ invariants.js        full-system audit
├─ services/aws/           Lambda handlers, DynamoDB/Stripe/SES/S3/Cognito adapters
├─ infra/template.yaml     AWS SAM (generated from the route table)
├─ web/                    React storefront (AWS mode or local mode)
├─ sim/                    simulator + sentiment evaluation
├─ tests/                  node:test suites
└─ docs/                   this site

Run it

npm test                 # unit, API, adapter and audit tests
npm run simulate         # experiments → results/ and this site
npm run dev:api          # local API on :8787 (whole cloud in-process)
cd web && npm run dev    # storefront (local mode without VITE_API_URL)

sam build -t infra/template.yaml
sam deploy --guided      # then set the Stripe keys in Secrets Manager
                         # and register /webhooks/stripe in Stripe

The full API description is in openapi.json, generated from the same route table.
